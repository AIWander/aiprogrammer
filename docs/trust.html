Official download boundary

No installer is offered from this site right now, and the earlier alpha is not linked here. When a verified signed build is published, use only the assets attached to that exact published version of the official Programmer-Wander GitHub release, and match the asset to Windows x64 or ARM64. A source archive, fork, copied executable, or build from another commit is a different artifact.

Signing and checksum verification

Published Programmer-Wander binaries and installers are Authenticode-signed and ship a SHA256SUMS asset. When a verified build is published, verify the file you actually downloaded before running it:

Get-AuthenticodeSignature .\Programmer-Wander-Setup-x64.exe |
  Select-Object Status, StatusMessage, SignerCertificate

Get-FileHash .\Programmer-Wander-Setup-x64.exe -Algorithm SHA256

Require a valid Windows signature and inspect the signer identity. Compare the SHA-256 value with the same release's SHA256SUMS. A checksum catches a mismatch against that list; Authenticode is the separate publisher-provenance check.

Release versus source

The public server release and the repository's current main branch can differ. A fix visible in source is not present in your installed binary until a new release contains it. Record the release tag when reporting a problem.

Known alpha identity defect: the current v0.2.0-alpha runtime can identify itself during MCP initialization as antigravity-rs version 1.0.0. That response is not proof that the installed Programmer product name and release version are correct. Use the downloaded asset, signature, hash, and release tag as the artifact record until a later release fixes and proves the handshake identity.

Runtime and permission boundary

  • Programmer exposes powerful local file, shell, git, process, data, and network tools to an MCP host.
  • It does not grant the host new operating-system permissions. The account running the host defines the real access boundary.
  • Consequential commands still require your review and the host's permission controls.
  • The plugin repository's guard hooks are opt-in templates. They are inert until reviewed, rendered, installed, trusted, and tested in a supported hook route.

Evidence

Inspect the server source, the plugin-kit source, the exact release notes, and the Apache-2.0 license. Source availability does not replace artifact verification.
